# Funnelo CRM

Sales CRM для невеликої команди продажів: канбан угод з drag & drop, компанії, контакти, таймлайн активностей, дашборд із прогнозом і лідербордом. Дві ролі (admin / user), права яких забезпечує Row Level Security у Postgres, а не лише інтерфейс.

- **Демо-вхід** (реєстрація не потрібна): на сторінці входу кнопки «Alex Morgan · admin» і «Jamie Carter · user», або вручну `admin@funnelo.test` / `user@funnelo.test`, пароль `Funnelo-demo-2026`.
- **Мова інтерфейсу:** англійська. **Теми:** світла, темна, системна.

## Ролі та права

|                                                  | user             | admin                  |
| ------------------------------------------------ | ---------------- | ---------------------- |
| Бачить усі компанії, контакти, угоди, активності | ✅               | ✅                     |
| Створює записи                                   | лише на себе     | на будь-кого           |
| Редагує / видаляє / перетягує                    | лише свої записи | будь-які               |
| Налаштовує етапи воронки                         | —                | ✅                     |
| Керує ролями й доступом                          | —                | ✅ (крім власної ролі) |
| Бачить журнал змін                               | —                | ✅                     |

Інтерфейс дзеркалить ці правила (замок на чужих картках, приховані кнопки), але справжній захист — RLS-політики й тригери в `supabase/schema.sql`. Навіть прямий запит до API з чужим `owner_id` поверне помилку.

Будь-хто, хто входить у Funnelo вперше, отримує роль **user**; admin призначає лише інший admin.

## Архітектура

```
app/                     маршрути; (app)/layout.tsx — єдина серверна точка "хто це"
components/              UI за розділами: deals, companies, contacts, activities, dashboard, settings
hooks/                   useCrmMutation, useMoveDeal, useRealtimeSync, useListParams, useTeam
lib/data/                усі запити до Supabase (один файл на сутність)
lib/query/               ключі кешу, queryOptions, карта інвалідації
lib/                     чиста логіка з тестами: board, position, csv, audit, activities, validation
supabase/                schema.sql, demo-data.sql
```

**Кешування й рендери**

- Ключі кешу — ієрархія (`["deals", "board"]`, `["deals", "list", params]`, ...). Після мутації `lib/query/invalidate.ts` інвалідує залежні гілки (угода → дашборд і суми компаній), перезапитуються лише активні запити.
- Відповідь сервера після редагування одразу кладеться в кеш картки: екран оновлюється без повторного запиту.
- Канбан оптимістичний: картка переїжджає миттєво, при відмові RLS — відкат і toast.
- Realtime-події з однієї пачки зливаються (debounce 400 мс) в одну інвалідацію. Структурне порівняння TanStack не перерендерить екран, якщо дані не змінились.
- Довідники (команда, етапи) — `staleTime` 10 хвилин, `select` з винесеними функціями (мемоізація Map без зайвих рендерів). React Compiler мемоізує компоненти.
- Таблиці: `keepPreviousData` — під час зміни сторінки/фільтра без миготіння скелетоном.

**Порядок карток** — дробові позиції: перетягування оновлює один рядок у БД (середнє між сусідами), а не перенумеровує колонку.

**Графіки** — HTML/CSS без бібліотеки: даних мало, кольори беруться з токенів теми, hover-підказки, прихована таблиця для скрінрідерів.

## База даних

Supabase-проєкт спільний для кількох проєктів портфоліо, тож усе — таблиці, функції, тригери, політики, view — має префікс **`funnelo_`**. Скрипти лише додають власні об'єкти; зі спільного вони торкаються тільки публікації `supabase_realtime` (додають `funnelo_deals` і `funnelo_activities`).

| Таблиця                                 | Що зберігає                                                           |
| --------------------------------------- | --------------------------------------------------------------------- |
| `funnelo_profiles`                      | учасник команди: ім'я, посада, роль, колір аватара, активний доступ   |
| `funnelo_pipeline_stages`               | етапи: порядок, ймовірність, тип `open / won / lost`                  |
| `funnelo_companies`, `funnelo_contacts` | акаунти й люди                                                        |
| `funnelo_deals`                         | угоди: сума, етап, позиція в колонці, дата закриття, причина програшу |
| `funnelo_activities`                    | дзвінки, листи, зустрічі, задачі, нотатки                             |
| `funnelo_audit_log`                     | журнал змін, пише тригер                                              |

Ключові рішення:

- **Без тригера на `auth.users`.** Користувачі спільні з іншими проєктами, тож профіль створюється ліниво RPC `funnelo_ensure_profile()` при першому вході саме у Funnelo.
- **RLS:** `funnelo_is_member()` / `funnelo_is_admin()` (security definer, щоб політики не зациклювались), читання — учасникам, запис — власнику або admin.
- **Тригери:** `closed_at` ставиться автоматично при переході у Won/Lost; роль і доступ змінює лише admin і не собі; Won/Lost не видаляються; журнал змін пише лише змінені поля.
- **`funnelo_dashboard()`** рахує всі метрики дашборду одним запитом; `funnelo_companies_list` (view з `security_invoker`) — суми й лічильники компаній для сортування на сервері.

## Як запустити

1. `npm install`
2. Скопіювати `.env.example` у `.env.local` і вписати URL та anon key спільного Supabase-проєкту.
3. У Supabase **SQL Editor** виконати по черзі:
   - `supabase/schema.sql` — схема, RLS, функції (безпечно перезапускати);
   - `supabase/demo-data.sql` — демо-команда з 6 менеджерів, 30 компаній, 70 контактів, ~100 угод за рік, ~240 активностей. **Скидає всі дані CRM** до початкового стану; дати рахуються від поточного дня, тож дашборд завжди «свіжий».
4. `npm run dev` → http://localhost:3000

## Тести

```bash
npm test          # юніт-тести: канбан, позиції, CSV, журнал змін, групування задач, валідація
npm run typecheck
npm run lint
```

Схему й демо-дані перевірено на реальному Postgres: повторний запуск обох скриптів, права user/admin/anon, тригери. Інтерфейс пройдено в Chromium (Playwright): обидві ролі, перетягування, форми, видалення.
