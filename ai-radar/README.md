# AI Radar

Каталог нових AI-продуктів поверх публічного [FreeSerp API](https://freeserp.ai/docs.php) (`index=sites`, ніша AI): пошук, фільтри, профілі сайтів, порівняння конкурентів і обране в акаунті.

**Демо:** _посилання на Vercel — додати після деплою_

**Тестовий акаунт** (реєстрація не потрібна): на сторінці входу є кнопка «Увійти як демо-користувач», або вручну `demo@demo.airadar.test` / `AIRadar-demo-2026`. В акаунті вже є кілька сервісів в обраному.

Стек: Next.js 16 (App Router) · TypeScript · Tailwind CSS v4 · next-intl (UA/EN) · Supabase (Auth + Postgres з RLS) · Motion (Framer Motion)

---

## План сайту

### Мета

- Дати зручну вітрину нових AI-продуктів: що з'явилося, у якій ніші, наскільки авторитетний домен.
- Скоротити шлях «знайшов → оцінив → порівняв → зберіг» до кількох кліків.

### Аудиторія

| Хто | Що їм потрібно |
| --- | --- |
| Фаундери й продакт-менеджери | аналіз конкурентів у своїй ніші, пошук ідей |
| Маркетологи й SEO | нові гравці ринку, DR, на чому зроблені сайти |
| Інвестори й скаути | ранні сигнали: свіжі запуски за нішами |
| Розробники | які стеки й AI-конструктори реально використовують |

### Сторінки та структура

```
/                     Головна: позиціонування, пошук, статистика індексу,
                      останні запуски, топ ніш, «на чому будують», лідери за DR
├── /catalog          Пошук + фільтри (ніша, стек, мін. DR, дати, сортування), пагінація.
│                     Усі фільтри в URL — посиланням можна поділитися
├── /site/[domain]    Профіль: AI-опис, факти, ніші, схожі сайти, «В обране», «Порівняти»
├── /compare          До 3 сайтів у таблиці, підсвічування найкращих значень (?d=a.com,b.ai)
├── /favorites        Обране користувача (Supabase)
├── /login            Вхід / реєстрація (email + пароль)
└── /about            Цей план
```

Усі сторінки доступні українською (`/uk/...`) та англійською (`/en/...`), є темна і світла теми.

### Як використано FreeSerp API

| Параметр | Де |
| --- | --- |
| `ai_startups=1` | скрізь — лише справжні AI-продукти |
| `q` | пошук у каталозі; точний пошук домену для профілю й порівняння |
| `ai_categories` | фільтр ніші, «схожі сайти» |
| `ai_source` | фільтр «зроблено на» і графік стеків на головній |
| `dr_min`, `from_date`, `to_date` | фільтри каталогу |
| `sort`/`order`, `size`/`from` | сортування й пагінація (до 10 000 результатів) |
| `stats=1` | статистика й топ ніш на головній |

## Що зроблено

- **Головна:** hero з пошуком, 4 метрики індексу, останні запуски, топ ніш і стеків (горизонтальні бари), лідери за DR.
- **Каталог:** повнотекстовий пошук, 5 фільтрів і сортування, чипи активних фільтрів, пагінація, порожній стан. Стан фільтрів зберігається в URL.
- **Профіль сайту:** опис, факти (DR, дати, стек, сервер, розмір), ніші, схожі сайти з тієї ж ніші.
- **Порівняння:** до 3 сайтів, підсвічування найвищого DR і найранішої дати. Можна поділитися посиланням, вибір зберігається між сесіями (localStorage).
- **Акаунт і обране:** реєстрація та вхід через Supabase Auth, обране в таблиці `ai_radar_favorites` з Row Level Security (кожен бачить лише своє), оптимістичне оновлення UI.
- **UA/EN** з перемикачем (зберігає поточні фільтри), переклад назв ніш.
- **Темна / світла тема** без «блимання» при завантаженні.
- **Адаптив:** мобільне меню, фільтри, що згортаються, без горизонтального скролу (перевірено Playwright на 375px і 1280px в обох темах).
- **Скелетони** для всіх сторінок із даними, **анімації появи** блоків (Motion), що вимикаються при `prefers-reduced-motion`.
- **Продуктивність:** усі запити до FreeSerp виконуються на сервері й кешуються на 10 хвилин. Головна статична з ревалідацією.

## Як запустити

```bash
npm install
cp .env.example .env.local   # вписати NEXT_PUBLIC_SUPABASE_URL і NEXT_PUBLIC_SUPABASE_ANON_KEY
npm run dev                  # http://localhost:3000
```

Для обраного потрібна таблиця в Supabase. У SQL Editor проєкту виконайте по черзі:

1. [`supabase/schema.sql`](supabase/schema.sql) — таблиця `ai_radar_favorites` і RLS-політики;
2. [`supabase/demo-account.sql`](supabase/demo-account.sql) — підтверджений демо-користувач із заповненим обраним.

Обидва файли можна безпечно перезапускати. Каталог, профілі й порівняння працюють і без Supabase.

Перевірки: `npm run lint`, `npx tsc --noEmit`, `npm run build`.

## Що не встиг

- Автотести (unit для `catalog-params` / `freeserp`, e2e для фільтрів і обраного).
- Вхід через Google/GitHub. Зараз лише email + пароль.
- Фільтр за кількома нішами одночасно: API приймає одну категорію за запит.

## Що доробив би далі

- **Колекції в обраному** (теги, нотатки) і email-дайджест «нові сайти у ваших нішах».
- **Сторінка ніші** (`/niche/[slug]`) з динамікою запусків за днями (`by_day` зі статистики) і SEO-метаданими.
- **Пошук у вебіндексі** (`index=web`): статті й огляди про конкретний сайт на його профілі.
- **Порівняння за трендом DR** та експорт таблиці в CSV.
- **Rate-limit і моніторинг** запитів до FreeSerp на рівні route handler.

## Як я працював з AI

Проєкт зроблено в Claude Code. Що робив сам:

1. Спершу попросив AI вивчити документацію й **реальні відповіді API**, а вже потім запропонувати ідеї. Обрав комбінацію каталог + новинки + порівняння.
2. Задавав рамки й архітектурні рішення: конвенція спільного Supabase (префікс таблиць `ai_radar_`), i18n і тема за зразком моїх попередніх проєктів, палітра за референсом, обране в акаунті замість localStorage.
3. Перевіряв результат у браузері й повертав конкретні баги: градієнтний текст, маска поля дати, переповнення карток на мобільному, мобільне меню. Для кожного просив знайти корінь проблеми, а не латати симптом.
4. Просив проганяти `tsc`, `eslint`, `build` і перевірку адаптиву в Playwright після кожної великої зміни.

Знахідки по даних, які варто знати:

- `went_live` — це дата, коли FreeSerp уперше побачив сайт «живим», а не офіційний запуск. База AI-стартапів зібрана приблизно із серпня 2026, тож фільтр дат працює саме в цьому діапазоні.
- Деяких відомих доменів (напр. `lovable.dev`) в індексі немає. Порівняння показує для них «немає даних».
