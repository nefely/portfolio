# AI Radar

Каталог нових AI-продуктів на публічному [FreeSerp API](https://freeserp.ai/docs.php) (`index=sites`, ніша AI). Можна шукати й фільтрувати сайти, дивитися профіль кожного, порівнювати конкурентів і зберігати сервіси в обране в акаунті.

- **Демо:** _посилання на Vercel — додати після деплою_
- **Тестовий акаунт** (реєстрація не потрібна): на сторінці входу кнопка «Увійти як демо-користувач», або вручну `demo@demo.airadar.test` / `AIRadar-demo-2026`. В обраному вже є кілька сервісів.
- **Мови:** українська (`/uk`) та англійська (`/en`). **Теми:** темна й світла.

## План сайту

> Той самий план є на сайті, на сторінці `/about`.

### Мета

- Дати зручну вітрину нових AI-продуктів: що з'явилося, у якій ніші, наскільки авторитетний домен, на чому він зроблений.
- Скоротити шлях «знайшов → оцінив → порівняв → зберіг» до кількох кліків.

### Аудиторія

| Хто | Що їм потрібно |
| --- | --- |
| Фаундери й продакт-менеджери | аналіз конкурентів у своїй ніші, пошук ідей |
| Маркетологи й SEO-спеціалісти | нові гравці ринку, DR, на чому зроблені сайти |
| Інвестори й скаути | ранні сигнали: свіжі запуски за нішами |
| Розробники | які стеки й AI-конструктори реально використовують |

### Сторінки та структура

```
/                     Головна
├── /catalog          Каталог із пошуком і фільтрами
│   └── /site/[domain]  Профіль сайту → «Порівняти» / «В обране»
├── /compare          Порівняння до 3 сайтів
├── /favorites        Обране (потрібен вхід)
├── /login            Вхід / реєстрація / демо-вхід
└── /about            План сайту
```

Основний сценарій: **головна або пошук → каталог з фільтрами → профіль сайту → порівняння з конкурентами → збереження в обране.**

## Які дані показуємо

Усі дані беруться з FreeSerp у момент запиту, у власній БД ми зберігаємо лише домени з обраного.

**Про кожен сайт** (поля відповіді `index=sites`):

| Що бачить користувач | Поле API |
| --- | --- |
| Домен, заголовок, фавікон | `domain`, `title` (іконка з Google Favicon service) |
| Опис продукту, згенерований AI | `ai_summary` (англійською, від FreeSerp) |
| Ніші (до кількох на сайт) | `ai_categories`, назви перекладено українською |
| Domain Rating 0–100 з кольоровою шкалою | `dr` |
| На чому зроблено (Lovable, v0, Bolt, Next.js, WordPress…) | `ai_source` |
| Коли сайт виявлено «живим» / уперше побачено | `went_live`, `first_seen` |
| Вебсервер, доменна зона, HTTP-статус, обсяг контенту, дата сканування | `webserver`, `tld`, `http_status`, `content_length`, `fetched_at` |

**Про індекс загалом** (`?stats=1`): кількість AI-продуктів, нові домени за 7 днів, кількість живих сайтів, топ ніш. Окремими запитами рахуємо, скільки AI-сайтів зроблено на кожному конструкторі, і скільки з'явилось за 30 днів.

### Як використано параметри API

| Параметр | Де використовується |
| --- | --- |
| `ai_startups=1` | скрізь: лише справжні AI-продукти, без шуму |
| `q` | повнотекстовий пошук у каталозі; точний пошук домену для профілю й порівняння (з `all=1`) |
| `ai_categories` | фільтр ніші, блок «Схожі сайти», топ ніш |
| `ai_source` | фільтр «Зроблено на», графік стеків на головній |
| `dr_min` | фільтр мінімального DR |
| `from_date` / `to_date` | діапазон дат появи |
| `sort` / `order` | сортування: найновіші, найвищий DR, релевантність, за алфавітом |
| `size` / `from` | пагінація по 24 (API віддає до 10 000 результатів) |
| `stats=1` | метрики й топ ніш на головній |

## Маршрути

Усі сторінки мають мовний префікс: `/uk/...` або `/en/...` (корінь `/` веде на `/uk`).

**Сторінки**

| Маршрут | Що на ній | Рендеринг |
| --- | --- | --- |
| `/` | hero з пошуком, 4 метрики індексу, останні запуски, топ ніш, «на чому будують», лідери за DR | статична, ревалідація раз на 10 хв |
| `/catalog` | пошук, фільтри (ніша, стек, мін. DR, дати, сортування), чипи активних фільтрів, пагінація | динамічна (стан у URL) |
| `/site/[domain]` | AI-опис, факти, ніші, схожі сайти, кнопки «Відкрити», «В обране», «Порівняти» | динамічна |
| `/compare?d=a.com,b.ai` | таблиця до 3 сайтів, підсвічування найвищого DR і найранішої дати | динамічна |
| `/favorites` | збережені сервіси користувача | статична оболонка, дані на клієнті |
| `/login` | демо-вхід, вхід, реєстрація | динамічна |
| `/about` | план сайту | статична |

**Службові маршрути**

| Маршрут | Призначення |
| --- | --- |
| `GET /api/sites?domains=a.com,b.ai` | профілі для списку доменів (до 24 за запит), використовується на сторінці «Обране» |
| `GET /auth/callback` | приймає посилання з листа підтвердження Supabase і створює сесію |

Невідомі шляхи віддають локалізовану сторінку 404, помилки API — сторінку з кнопкою «Спробувати знову».

## Архітектура

```
Браузер ──► Next.js (Vercel)
              ├─ Server Components ──► src/lib/freeserp.ts ──► FreeSerp API
              │    (головна, каталог, профіль,        (кеш fetch 10 хв)
              │     порівняння)
              ├─ /api/sites ─────────► src/lib/freeserp.ts ──► FreeSerp API
              └─ /auth/callback ─────► Supabase Auth
Браузер ──────────────────────────────► Supabase (anon key + RLS)
   (вхід, обране: select / insert / delete лише своїх рядків)
```

- **FreeSerp викликається тільки з сервера.** Типізований клієнт `src/lib/freeserp.ts` збирає запит і кешує відповідь через `fetch` на 10 хвилин. Так сторінки відкриваються швидко, а безкоштовне API не отримує зайвих запитів.
- **URL — єдине джерело стану каталогу.** `src/lib/catalog-params.ts` перевіряє параметри з URL і перетворює їх на параметри API. Будь-який вид каталогу можна передати посиланням.
- **Обране зберігається в Supabase.** Таблиця `ai_radar_favorites (user_id, domain, created_at)`, політики RLS дозволяють користувачу бачити й змінювати лише свої рядки. Браузер ходить у Supabase з anon-ключем, доступ обмежують саме політики. Інтерфейс оновлюється одразу, а якщо запит не вдався, зміна відкочується.
- **Порівняння працює без акаунта.** Вибір зберігається в `localStorage` і синхронізується з URL (`?d=...`).
- **Тема** перемикається через клас на `<html>`. Невеликий inline-скрипт ставить його ще до першого рендеру, тому сторінка не «блимає» іншою темою.

## Як запустити

Потрібно: Node.js 20+.

```bash
cd ai-radar
npm install
cp .env.example .env.local
npm run dev                  # http://localhost:3000
```

**Змінні оточення** (`.env.local`):

| Змінна | Звідки |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Project Settings → API |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | там само (anon / public key) |

Ключ FreeSerp не потрібен.

**База даних.** У Supabase SQL Editor виконайте по черзі:

1. [`supabase/schema.sql`](supabase/schema.sql): таблиця `ai_radar_favorites` і RLS-політики;
2. [`supabase/demo-account.sql`](supabase/demo-account.sql): підтверджений демо-користувач із заповненим обраним.

Обидва файли можна безпечно перезапускати. Каталог, профілі й порівняння працюють і без Supabase, без нього не працюють лише вхід і обране.

**Перевірки:** `npm run lint`, `npx tsc --noEmit`, `npm run build`.

## Деплой

Проєкт розгорнуто на Vercel з монорепозиторію `portfolio`:

1. **Root Directory:** `ai-radar` (Framework Preset: Next.js).
2. **Environment Variables:** обидві змінні з таблиці вище.
3. **Supabase → Authentication → URL Configuration:** додати домен Vercel у Site URL і Redirect URLs (`https://<домен>/**`), щоб посилання з листів підтвердження вели на сайт.

Кожен push у `main` автоматично перезбирає сайт.

## Що зроблено

- **Головна:** hero з пошуком і популярними запитами, 4 метрики індексу, останні запуски, топ ніш і конструкторів (горизонтальні бари з посиланнями на каталог), лідери за DR.
- **Каталог:** повнотекстовий пошук, 5 фільтрів і сортування, чипи активних фільтрів (кожен можна прибрати), пагінація, порожній стан. Стан зберігається в URL.
- **Профіль сайту:** опис, 9 фактів, ніші, схожі сайти з тієї ж ніші.
- **Порівняння:** до 3 сайтів, найвищий DR і найраніша дата підсвічуються. Можна поділитися посиланням або додати домен вручну.
- **Акаунт і обране:** реєстрація, вхід і демо-вхід в один клік через Supabase Auth. Обране захищене RLS, інтерфейс оновлюється одразу.
- **UA/EN:** перемикач зберігає поточні фільтри, назви ніш перекладено.
- **Темна / світла тема** без блимання при завантаженні.
- **Адаптив:** мобільне меню, фільтри, що згортаються, таблиця порівняння зі скролом усередині блоку. Горизонтального скролу сторінки немає: перевірено Playwright на 375px і 1280px в обох темах.
- **Скелетони** для всіх сторінок із даними, **анімації появи** (вимикаються при `prefers-reduced-motion`).
- **Стійкість:** сторінки помилки й 404, обробка доменів, яких немає в індексі («немає даних»).

## Що не встиг

- Автотести (unit для `catalog-params` і `freeserp`, e2e для фільтрів і обраного). Зараз перевірки ручні плюс скрипт адаптиву на Playwright.
- Вхід через Google чи GitHub, зараз лише email + пароль і демо-акаунт.
- Фільтр за кількома нішами одночасно: API приймає одну категорію за запит, тож довелося б склеювати кілька запитів.

## Що доробив би далі

- **Сторінка ніші** (`/niche/[slug]`): динаміка запусків за днями (`by_day` зі статистики), лідери ніші, SEO-метадані.
- **Пошук у вебіндексі** (`index=web`): статті й огляди про сайт прямо на його профілі.
- **Колекції в обраному** (теги, нотатки) і email-дайджест «нові сайти у ваших нішах».
- **Експорт** порівняння й обраного в CSV.
- **Rate-limit і моніторинг** запитів до FreeSerp, OG-зображення для профілів, sitemap.

## Як я працював з AI

Проєкт зроблено в **Claude Code** (агент Claude у VS Code; той самий інструмент доступний у вкладці «Code» в Claude Desktop). Що робив я, а що AI:

1. **Дослідження перед кодом.** Попросив AI спершу вивчити документацію й **реальні відповіді API**, і лише потім запропонувати ідеї. Із 5 варіантів обрав комбінацію каталог + новинки + порівняння.
2. **Рішення й рамки задавав я:** окрема сторінка для плану (на головній лише коротке позиціонування), обране в акаунті Supabase замість localStorage, конвенція спільного інстансу (префікс таблиць `ai_radar_`), i18n і тема за зразком моїх попередніх проєктів, палітра за референсом itlead.org, демо-акаунт для рецензентів.
3. **Перевірка результату.** Дивився сайт у браузері й DevTools і повертав конкретні баги: градієнтний текст, маска поля дати, переповнення карток на мобільному, розміщення елементів у мобільному меню. Для кожного просив знайти корінь проблеми, а не латати симптом.
4. **Контроль якості.** Після кожної великої зміни AI проганяв `tsc`, `eslint`, `build` і перевірку адаптиву в Playwright.

**Знахідки щодо даних:**

- `went_live` означає дату, коли FreeSerp уперше побачив сайт «живим», а не офіційний запуск. Базу AI-стартапів зібрано приблизно із серпня 2026, тому фільтр дат має сенс саме в цьому діапазоні.
- Деяких відомих доменів (наприклад, `lovable.dev`) в індексі немає. Для них профіль показує «Сайт не знайдено», а порівняння пише «немає даних».
- Фільтр `ai_categories` приймає одну нішу: якщо передати кілька, API мовчки бере останню.
